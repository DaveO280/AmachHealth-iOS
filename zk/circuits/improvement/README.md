# AverageImprovementProof

Generic Groth16 circuit that proves a claimed average-improvement
percentage was honestly computed from values committed in v2 (124-byte)
Amach Merkle leaves. Spring Push Season One uses this to prove VO2 max
gains for prize payouts on zkSync Era; future seasons reuse the same
template parameterised against any 16-bit metric in the v2 leaf.

```
                       ┌─────────────────────────────────┐
   public inputs ───►  │  AverageImprovementProof(N,M,d, │
                       │           chunkIdx,offsetInChunk)│
   private witness ─►  │                                 │  ─► proof
                       │   ▼                             │
                       │ MetricExtraction × (N+M)        │
                       │ MerkleInclusion  × (N+M)        │
                       │ AverageComputation × 2          │
                       │ SignedImprovementCheck          │
                       └─────────────────────────────────┘
```

## Public inputs (5 signals)

| Signal              | Meaning |
|---------------------|---------|
| `baselineRoot`      | committed Merkle root for the baseline window |
| `finishRoot`        | committed Merkle root for the finishing window (often == baselineRoot if a single tree spans both) |
| `metricPointer`     | byte offset inside the v2 leaf — must equal `chunkIdx*31 + offsetInChunk` (compile-time pinned) |
| `claimedMagnitudeBp` | claimed `|improvement|` in basis points (`1234 = 12.34 %`) |
| `claimedSignFlag`    | `0` = improvement, `1` = decline |

## Default instantiation

```
component main = AverageImprovementProof(2, 2, 7, 2, 2);
```

| Parameter                     | Value | Meaning |
|-------------------------------|------:|---------|
| `N`                           | 2     | baseline-window leaf count |
| `M`                           | 2     | finish-window leaf count |
| `depth`                       | 7     | Merkle tree depth (max 128 leaves) |
| `METRIC_CHUNK_IDX`            | 2     | chunk index that holds vo2max |
| `METRIC_BYTE_OFFSET_IN_CHUNK` | 2     | byte offset inside chunk 2 |

These values resolve to: VO2 max at leaf byte 64, two-day baseline / two-day
finish averages, against a 128-leaf tree.

## Constraint cost

Measured (default instantiation):

| | |
|---|---|
| Constraints       | **18,707** (under the 20 k brief target) |
| Wires             | 18,744 |
| Public inputs     | 5 |
| Private inputs    | 76 |

The dominant per-leaf costs:

| Component                | Constraints / leaf |
|--------------------------|-------------------:|
| `MetricExtraction`       | 986 (Poseidon4 + Num2Bits(248)) |
| `MerkleInclusion(7)`     | ~3,654 (7 Poseidon(2) + swap arithmetic) |

Bigger windows or deeper trees scale linearly; see the table in
`improvement.circom` header comments for back-of-envelope numbers.

## Build & trusted setup

```
cd zk

```

This compiles the circuit, runs a Phase-2 ceremony reusing
`pot17_final.ptau` (Phase 1, generated by `setup_phase4.sh`), exports the
verification key, generates the Solidity verifier
(`AverageImprovementProofV1Verifier.sol`), and mirrors the verifier into
the `Amach-Website/contracts/` repo.

## Generate a proof

```js
const { buildImprovementWitness } = require('./scripts/build_improvement_witness');
const { hashLeafV2, buildTestLeafV2 } = require('./scripts/hash_leaf');
const snarkjs = require('snarkjs');

const baseline = [buildTestLeafV2({ dayId: 1, vo2max: 400 }),
                  buildTestLeafV2({ dayId: 2, vo2max: 410 })];
const finish   = [buildTestLeafV2({ dayId: 50, vo2max: 440 }),
                  buildTestLeafV2({ dayId: 51, vo2max: 451 })];

const { input } = buildImprovementWitness({
  baselineLeaves: baseline,
  finishLeaves:   finish,
  baselineIndices: [0, 1],
  finishIndices:   [0, 1],
  metricChunkIdx: 2,
  metricByteOffsetInChunk: 2,
  N: 2, M: 2, depth: 7
});

const { proof, publicSignals } = await snarkjs.groth16.fullProve(
  input,
  'build/improvement/improvement_js/improvement.wasm',
  'build/improvement/improvement_final.zkey'
);
```

`publicSignals` is the 5-element array consumed by
`Groth16Verifier.verifyProof(...)` on-chain.

## Adding a new metric

Per-metric verifiers are how we maintain the strong byte-offset binding
without paying for a runtime multiplexer (see
`metric-pointers.md → "Multi-metric circuit?"`):

1. Pick the metric's `(METRIC_CHUNK_IDX, METRIC_BYTE_OFFSET_IN_CHUNK)`
   from `metric-pointers.md`.
2. Edit `improvement.circom`'s default `component main` line, or
   instantiate from another circuit file.
3. Re-run `./setup_improvement.sh`.
4. Deploy the new verifier at a new address (the address is what binds
   on-chain consumers to "this is the RHR verifier", not a constant
   inside the contract).

## Binding model — what this circuit *does* and *does not* prove

The circuit binds:

- **Leaf-content integrity.** Every leaf used in the average has its four
  31-byte chunks committed via `Poseidon4(chunks) === leafHash`.
- **Inclusion.** Each leaf hash is in the tree under the public root
  (Poseidon(2) Merkle path).
- **Metric extraction.** The 16-bit value at `(chunkIdx, offsetInChunk)`
  is reconstructed from the chunk's bits — no chance of "actually we
  used HRV instead of VO2 max".
- **Improvement equation.** `claimedMagnitudeBp · baselineSum · M ==
  10000 · |finishSum · N − baselineSum · M|`, with `claimedSignFlag`
  selecting the direction. The selected diff is range-checked, which is
  what forces the sign flag to be honest.
- **Pointer/instantiation alignment.** The public `metricPointer` MUST
  equal the compile-time chunkIdx*31+offsetInChunk; tampering with the
  pointer fails witness generation.

The circuit does NOT bind:

- **Day IDs / contiguity / windowing logic.** Whether the chosen
  baseline-and-finish leaves are *the right days* for a given contest is
  enforced by the off-chain legitimacy script (Layer 1) and the
  on-chain registry that tracks which roots correspond to which window.
  The circuit only certifies the math against whatever leaves the prover
  selected.
- **That the average is statistically meaningful.** With N=M=2 the
  baseline/finish are two-day means. Whether that is enough to declare a
  "real" improvement is policy, not crypto.

Both gaps are intentional — they keep the circuit small enough to fit
the 20 k constraint target while allowing per-season policy to evolve
without recompilation.
